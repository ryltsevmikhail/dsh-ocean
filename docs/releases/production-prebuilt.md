# Reviewed production prebuilt signing

The production lock binds the accepted Ocean 0.1.2 source commit and exact archive bytes for Linux x86_64 and aarch64. Ocean uses stable sequence 1; DSH uses next sequence 2. Existing RC locks/workflows/keys/releases remain unchanged. Product tags identify the build source, not the later workflow commit.

`production-prebuilt.yml` is manual and defaults to validation only. It consumes existing unpublished drafts and never builds replacement payloads or publishes. Signing uses the existing protected product environments, owner-clearance variable and independently pinned public-key fingerprint. The independent verifier is built from the exact accepted product source. Runtime imports are separate private, unselected generations, not activation/health claims. Both archive targets are validated before signing, then checked again before metadata upload. Uploads address the captured release ID, never a mutable tag lookup; existing metadata is never overwritten.

Only one operator may mutate each release during staging/signing/acceptance/publication. GitHub does not offer an atomic conditional draft-state asset upload. Do not run the separate publisher while this workflow is executing; identity/state checks detect concurrent changes but cannot make a concurrent third-party publication safe. On partial upload, inspect the draft and existing exact metadata before any retry; never resign a used sequence with different bytes.

After signatures are uploaded, independently compare public-key fingerprints to the previously authenticated records, verify exact signed bytes with both native builds, and complete private activation/rollback checks. Only then may the separate reviewed publisher verify every remote asset, tag and captured release ID, add the final notes, and publish Ocean stable and runtime next. Download all signed artifacts publicly after publication and recheck signatures/hashes. Working profiles, installations and servers are excluded.

The source/plugin companions already published with runtime r1 remain immutable and available at no additional charge. Native and JavaScript source mappings/notices and ARM source recipe snapshot are retained in the runtime archives. Debian packages are supplemental assets, not managed-feed inputs. No Python-runtime, Electron, AppImage, provider or arbitrary plugin-profile acceptance is implied.
