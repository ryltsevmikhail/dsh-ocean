# Signed first installation design

User requires working installation from zero before stable, and explicitly approved Ocean0.1.3 stable preserving reserved0.1.2. DSH next0.2.0-rc.2.ocean.2 and plugin0.20.1-ocean.1 unchanged. Existing signed candidates remain unpublished, immutable tags and old bytes preserved.

Implementation choice (delegated by repeated requests to finish): replace GUI npm bootstrap with a Rust signed prebuilt first-install operation; retain legacy maintenance modes. Existing signature/domain/policy/native-target checks, archive import and native health are reused. Existing runtime key is embedded as public data, not fetched; exact nextseq2 release/components/artifact hashes are pinned. No automatic write to updater trust/settings. No npm fallback or downgrade of existing runtimes.

Operation takes setup one-shot + runtime permit; refuses any detected existing runtime/server or legacy/foreign selector. Cancellation is operation-owned Control, active through download/import/isolated native health. It commits only after exact revalidation and inventory check. New first-install journal binds intended selector/floor; current is created without overwrite. Exact runtime floor is recorded after selector; journal is removed durably. Startup and maintenance refuse incomplete journal. Retry recovers only its own exact incomplete selector, retaining conservative floors/imports; corrupt journal or foreign selector refuses. No profile/service state is modified in preparation. After completed install release permit, invalidate probe cache and invoke existing localized service setup/consent.

Normal network/disk/signature/health failure or cancellation before commit leaves no selected runtime. Crash recovery must not execute an uncompleted selection. Commit cannot be falsely reported cancelled. Review correction: a stable installer cannot expire with its14day mutable-update metadata. First installation therefore has a distinct immutable-bootstrap policy: existingkey authentication plus compiled exactmetadataSHA/release/seq/components/botharchivehashes, independent of updater expiry. No catching expiry failures and retrying; no fakeclock. Ordinary verifier/updater freshness and anti-equivocation stay unchanged. CompiledsignedOcean authenticates this immutable contract. This implementation choice resolves the concrete production defect under the user's delegated fix authorization.

Review focus: trust/policy confusion; unsafe paths/symlinks; concurrency/lock order; quit/cancel ownership and late commit; crashes at selector/floor boundaries; existing external runtime refusal; reuse of imports after tamper; no silent updater enrollment; real zero-runtime native GUI behavior botharchitectures. Runtime publication/public first-install validation precedes shell stable promotion.

Final review found four Important issues; one fix pass in progress. Ruling: immutable bootstrap lifetime is confined to exact compile-pinned metadata/archive bytes; mutable updater policy is unchanged. Cost if wrong: a retired but still available fixed runtime remains installable through this specific Ocean version; correcting that requires a new Ocean release. This is preferable to silently breaking stable installation after14days.
